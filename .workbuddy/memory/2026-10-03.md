## ★ 重大发现：dl.sampledir.com 强制 Referer，无 Referer 一律 403
- R2 桶 sampledir/releases/ 下三个文件都在（dmg 10-01、pkg 10-01、exe 10-03 12:08 win 脚本上传）。
- 403 与文件无关，是 Cloudflare 侧规则（猜测 WAF/防盗链/Bot Fight 规则匹配"Referer 不存在"）：
  - 裸请求 → 403；带 Referer: https://www.sampledir.com → 200/206。
  - r2.dev 域名也 500（非公开桶特征）。
- 影响面：
  - 官网按钮（`<a target=_blank>` 跨源带 Referer）→ 能下，不致命。
  - **客户端 Sparkle / NSURLSession 下载无 Referer → 403，更新下载挂**（appcast enclosure 三个 URL 全是 dl.sampledir.com）。
  - 用户粘贴直链到地址栏手动下载 → 403。
- 对照：GitHub Release 直链裸请求 200/206，不受影响。
- **用户 2026-10-03 明确表态：这是故意设置的防盗链，只走网页下载，不要去改 CF 规则**（因此「客户端 Sparkle 下载 403」属已知设计，不算事故，后续别重复报这个）。
- 因此客户端更新下载不要指望 R2 直链；若要客户端可直下，需自行决定是否加 Referer 白名单 / 换 GitHub 直链。

## 下载区平台化：Windows 访客默认展开 Windows 面板（commit 5b1f1d7，已上线）
- 需求（2026-10-03）：不要动 mac 的自动下载逻辑；Windows 从 App 点更新，应「跳到 Windows 下载区再自动下载」。
- 原问题：Windows 浏览器打开 /download 时，HTML 里写死 mac 的 `is-active` + `#dlPanelWindows hidden`，用户看到的是 macOS 面板（自动下载虽点 exe，但页面是 mac 的）。
- 修复：
  - main.js 新增 `isWinBrowser()`（唯一 UA 判定源，tryAutoDownload 与 tab 初始化共用）
  - `initPlatformTabs` 抽出 `selectPlatform(platform)`，首次进入按浏览器平台预选 tab：Win→windows、其余→macos（`selectPlatform(isWinBrowser() ? 'windows' : 'macos')`）
  - 新增 `applyPlatformIntro()`：下载区导语 `#dlIntro` 按平台取 `dl.p.win` / `dl.p`，写在 applyLang 末尾（切语言也保持），**mac 侧仍走原 `dl.p`，行为零变化**
  - i18n 四语补 `dl.p.win`（zh/en/ko/ja）；index.html 给导语 `p[data-i18n=dl.p]` 加 id="dlIntro"
- 验证手法（可复用）：`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome --headless=old --disable-gpu --user-agent="<Win/Mac UA>" --virtual-time-budget=4000 --dump-dom <url>` → 解析 `#dlPanelWindows/#dlPanelMacos` 的 hidden、`.dl-tab.is-active`、`#dlIntro` 文本。headless=new 在本机 dump 为空，用 old。
- 线上结论：Win UA → Windows 面板可见/mac 隐藏/Windows tab active/导语「支持 Windows 10+ x64」/自动下载点 exe；Mac UA → 与改动前完全一致。

## ★ 自动下载后页面没滚到下载区（commit 0e75b7a，已上线）
- 现象（2026-10-03）：Windows 从 App 点「更新」→ 文件下载了，但页面停在 Hero/顶部，看不到下载面板。
- **根因**：站点 CSS `html{scroll-behavior:smooth}`（assets/css 第22行），`#download` 锚点是平滑滚动动画；
  而 `#dlWinR2` 的 href 在 HTML 里就是**写死的真实 exe 地址**，脚本解析阶段立刻 `location.assign` 导航，
  **平滑滚动动画被导航打断 → 等于没滚**。mac 侧 `#dlR2` 初始 href 是 `'#'`、要等 version.json 那一拍（~300ms），
  平滑滚动早跑完，所以 mac 看起来一直正常——这就是「只有 Windows 有问题」的真正原因，不是 UA 判定错。
- 修复（mac 表现不变，滚到的是同一位置）：
  - `tryAutoDownload` 里把导航包成 `fireDownload()`，**先 `sec.scrollIntoView({block:'start',behavior:'instant'})`**
    强制瞬时滚动（绕开 CSS smooth），老浏览器 try/catch 退回默认；
  - 等 `document load`（布局稳定）后 + 120ms 再导航，保证滚动先渲染出来再切走。
- 验证手法（重要，可复用）：把站点复制到 /tmp，用 python 注入探针
  `setTimeout(...document.title='scrollY='+window.scrollY+' titleTop='+download.getBoundingClientRect().top...)`，
  再把 `window.location.assign(href);` 替换成 `window.__ASSIGNED__=href;` 禁掉真实下载，
  然后 `Chrome --headless=old --user-agent="<Win UA>" --virtual-time-budget=8000 --dump-dom "file://...?autodl=1#download"`。
  - `--headless=new` 本机 dump 为空，必须用 `--headless=old`；
  - 片段滚动在 headless=old 下确实生效（对照页 3000px spacer 实测 scrollY=2931），探针可信；
  - 修前 Win/mac 都是 scrollY=0，修后两者都 titleTop=0（首页 scrollY=8739）。
- 注意：`https://www.sampledir.com/index.html` 返回 **308**，curl 要 `-L`；抓首页用 `https://www.sampledir.com/`。
