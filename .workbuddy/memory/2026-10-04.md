# 官网 SampleDir 工作日志（2026-10-04）

## 下载卡片整卡悬停高亮（commit `f3a1d99`）
- 需求：鼠标移到哪张下载卡，哪张亮；现状是「只有一个一直亮」。
- 根因：`.dl` 卡片**完全没有 hover 样式**，只有卡内按钮各自 hover —— `btn--primary`（官方下载）
  常驻绿渐变 + `box-shadow: 0 8px 24px rgba(0,230,118,.28)`，视觉上独占"亮"，其余卡灰扑扑。
- 修法（只动 `assets/css/styles.css`，macOS / Windows 面板共用）：
  - `.dl` 加 `transition: transform .2s, border-color .2s, box-shadow .2s, background .2s`
  - `.downloads .dl:hover, .downloads .dl:focus-within` → border 转 `var(--green)`、
    background `var(--surface)`→`var(--surface-2)`、`translateY(-4px)`、`box-shadow: 0 14px 34px rgba(0,0,0,.3)`
  - `.dl__icon` hover 转实心绿块 `background: var(--green)` + `scale(1.08)`，
    图标 svg 统一 `fill/stroke: #06231a`（覆盖 `.dl--github`/`.dl--windows` 的绿填充）
  - `.dl__icon` 补 transition
- ★ 坑：选择器必须带 `.downloads` 前缀（`.downloads .dl:hover` 特异性 0,3,0）。
  否则后面的 `.reveal.in{transform:none}`（0,2,0）……其实特异性更低，真正的风险是
  `.reveal{transform:translateY(24px)}` 与 hover 位移在进场动画期打架；带前缀最稳。
- 验证手法（本机 headless Chrome 截图管线出不来内容，改用计算样式比对）：
  1. 把 `:hover` 文本替换成 `.hl` 模拟类（`python` 改 CSS 副本）
  2. 探针追加 `transition: none !important` 关掉过渡，否则 `--virtual-time-budget` 下
     getComputedStyle 返回插值起始值（会误判「位移没生效」）
  3. `getComputedStyle` 读 border/background/transform/box-shadow/iconBg 对比 hover 与常态，
     结果插进 `<div id="R">` 再用 `grep -o 'id="R">[^<]*'` 取（`document.title=` 常读不到）
  4. Windows 面板初始 hidden，测 hover 要先 `document.querySelector('[data-platform="windows"]').click()`

## 下载卡按钮统一亮绿（2026-10-04，commit 47ddfd0，已 push 上线）
- 现象：每张下载卡第一个按钮是 `btn--primary`（绿渐变常驻），第二个是 `btn--ghost`
  （`background: var(--surface-2)` 灰黑底 + 灰边），所以"第一个永远亮绿、第二个永远黑"。
- 解法（纯 CSS，不改 HTML class，避免动 fireDownload/自动下载链路）：在 `.dl .btn{width:100%}` 后加
  `.dl .btn{background:linear-gradient(135deg,var(--green),var(--green-2));color:#06231a;border-color:transparent;box-shadow:0 8px 24px rgba(0,230,118,.28)}`
  + `.dl .btn:hover,.dl .btn:focus-visible{transform:translateY(-2px);filter:brightness(1.07);box-shadow:0 14px 32px rgba(0,230,118,.45)}`。
  特异性 `.dl .btn`(0,2,0) 压过 `.btn--ghost`(0,1,0)，写在文件靠后位置覆盖 `.btn--primary:hover`。
- 验证：本地 `python3 -m http.server` + agent-browser（本机裸 Chrome `--headless=old --dump-dom`
  在沙箱里会 SIGTERM/无输出，别用）。eval 读 5 个按钮（dlR2/dlGithub/dlWinR2/dlWinGithub/dlWinMsi）
  computed backgroundImage 全是 linear-gradient(0,230,118)；hover 第二张卡 → 按钮 transform -2px、
  卡片 border rgb(0,230,118)、背景提亮。截图 mac/win 两端按钮均亮绿。
- 坑：`git add -A` 会把我自己写的 `.workbuddy/memory/*.md` 也带进 commit（该目录未 gitignore），
  提交前先 `git reset HEAD -- .workbuddy/` 再 commit，或单独 add `assets/css/styles.css`。

## 下载按钮"悬停才亮绿"——用户真实意图（2026-10-04，commit 9b5ae2b 修正）
- 用户要的是：**默认态维持原样**（第一张 `btn--primary` 亮绿、其余 `btn--ghost` 灰黑），
  **鼠标移到哪张哪张整卡（含按钮）亮绿，移开立刻还原**。上一版把所有按钮常驻亮绿是改错了，已 `git revert` 撤掉。
- 正解 CSS（只加这一段，不动 `.dl .btn{width:100%}` 与 HTML class）：
  `.downloads .dl:hover .btn, .downloads .dl:focus-within .btn { background:linear-gradient(135deg,var(--green),var(--green-2));
  color:#06231a; border-color:transparent; box-shadow:0 8px 26px rgba(0,230,118,.36); transform:translateY(-2px); }`
  特异性 (0,3,0) 压过 `.btn--ghost`(0,1,0) 和 `.btn--primary:hover`(0,2,0)；`:focus-within` 让键盘 Tab 也亮。
- 验证手法：本地 `python3 -m http.server`（**必须 run_in_background**，普通 Bash 启的进程随调用结束被杀，
  浏览器会 ERR_CONNECTION_REFUSED）+ agent-browser（`agent-browser open` / `hover` / `mouse move 5 5`（移开还原）
  / `eval` 读 computed style / `screenshot`）。裸 Chrome `--headless=old --dump-dom` 在沙箱里必 SIGTERM，别用。
- 实测：hover #dlGithub → 按钮 bgImg=linear-gradient(0,230,118)、transform -2px、卡片绿边；
  mouse move 到 (5,5) → 按钮 bgImg=none 还原、卡片边框回 rgb(42,42,64)。截图 idle/hover 两端一致。
- 但用户截图反馈"两张一起亮了"——因为第一张是 **常驻亮绿** 的 primary，非悬停卡并没被压灰。
- **最终版（commit eef79b8）＝互斥高亮**：默认第一张绿、其余灰；一旦有卡被悬停/聚焦，
  其余卡的按钮与图标一并压回灰黑（连常绿的第一张也变灰），保证"只有一张亮绿"。
  关键选择器：`.downloads:has(.dl:hover) .dl:not(:hover) .btn{background:var(--surface-2);color:var(--text);border-color:var(--border);box-shadow:none;transform:none}`
  加同形的 `.dl__icon` / `.dl__icon svg` 两条。`:has()` 不支持时只是少压灰、本卡变绿照旧，天然降级。
- 实测矩阵（computed backgroundImage）：hover 第 2 张 → dlR2=none / dlGithub=gradient；
  hover 第 1 张 → 反过来；移开(5,5) → 回到默认 dlR2=gradient / dlGithub=none。Windows 面板同。
- **截图时机坑**：`agent-browser hover` 后立刻 eval 会读到 transform 过渡中间态（matrix(…,0)），
  等 ~0.5s 再读才准。截图要 `sleep 0.4~0.5` 后再 `screenshot`。
- 切平台 tab 验证时 `agent-browser click .dl-tab[data-platform=windows]` 有时不切换，
  用 `eval "...querySelector('.dl-tab[data-platform=windows]').click()"` 稳；再 eval 校验
  `#dlPanelWindows.hidden===false && #dlPanelMacos.hidden===true`。

## Windows 卡图标悬停即隐形（2026-10-04，commit df49a5e）
- 现象：Windows 卡（官方下载 / MSI）图标平时是淡绿底 + 绿色描边；鼠标一悬停，
  图标底被 `.downloads .dl:hover .dl__icon{background:var(--green)}` 变实心亮绿，
  而 svg 走全局 `fill:none;stroke:var(--green)` → 绿描边在绿底上直接消失，只剩中间空心四边形。
- 修：两张 Windows 卡加 `dl--windows` 类，`CSS .dl--windows .dl__icon svg{fill:#06231a;stroke:none}` → 深色实心 Windows 四格窗，
  淡绿底/亮绿底都清晰。删掉没人用的 `.dl--windows{border-style:dashed}`（会导致误加时卡片变虚线框）。
- 坑：`.dl--windows` 必须挂在 Windows 面板内的卡上；MSI 卡原本是 `dl reveal dl--github`，改成 `dl reveal dl--windows`。

## Windows 徽标改四格实心 + 默认/悬停两态分明（2026-10-04，commit 08fc6bf）
- 现象①「没选中状态」：默认态 svg 用深色 `#06231a` 压在 `--green-soft`(rgba(0,230,118,.12)) 深绿图标底上，
  几乎看不出来；②悬停时四格糊成一整块黑方块。
- 根因②：旧 path `M3 5.55 10.5 4.5v7H3v-5.95z...` 是 4 段**互相重叠**的子路径（左上格 x3~10.5、右上格 x8.5~21），
  fill 时重叠区并成一体，靠斜边才勉强分出形状 → 只要 fill 就必然糊。描边态才好看。
- 修：
  - `index.html` 两张 Windows 卡（官方下载 / MSI）图标换成 **4 个独立 `<rect>`**（`x=3/13,y=3/13,8×8,rx=1.2`，
    格间 2 单位真缝隙），class `ico-win`；改后 `.dl--windows svg path` = 0、`rect` = 8。
  - `CSS .dl--windows .dl__icon svg{fill:var(--green);stroke:none}` 默认**亮绿**（与 GitHub 图标一致）；
    悬停时 `.downloads .dl:hover .dl__icon svg{fill:#06231a}` 特异性 (0,4,1) 本就压过 (0,2,1)，
    自动转深色压在实心亮绿底上 → 一浅一深两态。
- 验证（agent-browser，Windows 面板）：默认 svgFill=rgb(0,230,118)/iconBg=rgba(0,230,118,.12)；
  悬停 svgFill=rgb(6,35,26)/iconBg=rgb(0,230,118)/scale 1.08；截图两端都是清晰四格。
- 坑：CF 缓存 CSS 时 `grep -c` 中文注释可能查不到，以 grep 实际规则行（`dl--windows .dl__icon svg`）为准。
